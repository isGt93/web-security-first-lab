# 第一次完成 Web 安全实验 · 随书靶场

《第一次完成 Web 安全实验》的配套代码。使用一个虚构的校园活动网站，练习正常流程、问题验证、修复对照与实验记录。

作者：[ailx10 / isGt93](https://github.com/isGt93)。

## 快速开始

需要 Python 3.10 或更高版本，仅使用标准库，无需安装第三方依赖。

```bash
git clone https://github.com/isGt93/web-security-first-lab.git
cd web-security-first-lab
python lab.py --mode vulnerable
```

在浏览器打开 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。

| 用户名 | 密码 |
| --- | --- |
| alice | alice |
| bob | bob |

Windows 上如果 `python` 命令不可用，可以尝试 `py -3 lab.py --mode vulnerable`。启动后保持终端运行，按 `Ctrl+C` 停止。

## 建议练习顺序

1. 登录 alice，查看自己的账户与资料，先确认正常流程。
2. 查看请求和响应，改变一个输入，记录结果与正常流程的差异。
3. 停止漏洞版，启动修复版，重新登录，对照相同条件下的结果。
4. 使用 [实验记录模板](docs/实验记录模板.md) 整理条件、步骤、证据与结论。

```bash
python lab.py --mode fixed
```

两种模式使用相同的默认端口，需要先停止前一种模式。重启会清空会话、账户修改、留言和附件。

## 实验内容

| 内容 | 页面 | 修复对照 |
| --- | --- | --- |
| 越权访问 | `/profile?id=1` | 服务器检查资料所属用户 |
| SQL 注入 | `/login` | 参数化查询 |
| 反射型 XSS | `/search` | 输出转义 |
| 存储型 XSS | `/comments` | 留言输出转义 |
| CSRF | `/account`、辅助站点 `http://127.0.0.1:8766/` | 校验会话绑定的 CSRF 令牌 |
| 文件上传 | `/upload` | 文件名、类型、内容和大小检查 |

具体对照逻辑以 `lab.py` 为准。所有账户与资料均为虚构；服务仅监听 `127.0.0.1`。上传文件仅保存在内存中，并以纯文本附件下载，不执行脚本。`fixed` 用于展示书中的六类控制，不是生产系统模板。

## 端口冲突

```bash
python lab.py --mode vulnerable --port 8875 --attacker-port 8876
```

此时主站为 `http://127.0.0.1:8875/`，辅助站为 `http://127.0.0.1:8876/`。实验请求中的端口也需要同步修改。

## 自动检查

```bash
python check_lab.py
```

检查正常登录、会话与资料访问，以及六类问题在漏洞版和修复版的差异。测试使用本机端口 `18865`、`18866`、`18875`、`18876`，结束后自动关闭测试服务。

## 常见问题

| 现象 | 先检查 |
| --- | --- |
| 页面无法访问 | 终端中的进程是否还在运行；地址、端口是否正确 |
| 提示端口被占用 | 停止之前的实验进程，或使用自定义端口 |
| 切换模式后失去登录状态 | 重启会清空数据，需要重新登录 |
| CSRF 辅助页面没有效果 | 主站是否已登录；主站与辅助站是否使用同一个 `127.0.0.1` 主机名 |
| 上传文件重启后消失 | 文件仅保存在内存中，属于预期行为 |
